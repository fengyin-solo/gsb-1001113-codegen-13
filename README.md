# 市政道路桥梁养护管理平台

覆盖道路巡查、桥隧定检、路面病害、交安设施、绿化管养、除雪防汛及养护工程管理的市政道桥全要素养护后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 防汛事件驱动分拨器（`/api/dispatch`，前端「防汛分拨」）

四类上游信号走同一条管线，页面不得各自判断升级结论：

```
水位告警 / 泵站排水离线 / 边坡偏离 / 道路巡查
  → 适配器归一成统一写法
  → 事件指纹（来源|事件类别|位置|对象编号）合并重复告警
  → 事件版本累加 + 升级链（只升不降）
  → 按前置件展开处置树（橙/红级追加管制、转移节点）
  → 单事务投影：防汛台账(flood)、排水设施清单(drainage)、养护工程汇总(project)
```

口径约定：

- **指纹合并**：同指纹告警合并为一个事件并累加次数；事件结束后同指纹再报，另立新事件，
  历史事件的升级链定格不变。
- **版本与重放**：信号带 `source_version`，旧版本消息重放只记 `replay` 留痕，不进升级链，
  绝不降低已确认预警级别；跨模块写入在 `store.transaction()` 内完成，失败整库回滚，
  事件状态与投影行的「事件版本」保持一致。
- **指挥部命令**：现场管制结论永远以指挥部最新命令为准（命令可带 `command_seq` 防乱序、
  请求可带 `expected_version` 做乐观锁，冲突返回 409）；命令级别低于已确认预警时，
  只更新管制动作，确认级别不降级。
- **处置树**：节点必须前置件全部完成才能启动；橙色以上才追加交通管制节点，红色追加人员转移；
  全部节点完成后才允许结束响应。
- **投影规则**：泵站离线写排水设施清单（恢复后回写正常）；事件达橙级立「防汛应急抢修工程」、
  结束后回写竣工；所有投影行带 `数据来源=事件分拨器`、关联事件编号与事件版本，各页面只展示。
